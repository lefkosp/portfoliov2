Frontend architecture is less about creating a perfect abstraction and more
about preserving clarity under change.

## Start With Boundaries

Useful systems define where decisions belong. Layout, data access, interaction
state, and visual tokens should not compete for ownership inside the same
component.

When those boundaries stay visible, teams can move faster without turning the
interface into a collection of local exceptions.

## Make Repetition Intentional

Not every repeated line needs an abstraction. The better question is whether
the repetition describes a stable product rule or just a coincidence in the
current screen.

Frontend systems stay legible when abstractions are introduced after the rule is
clear.
